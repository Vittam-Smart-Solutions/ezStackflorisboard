## AI Policy — read before writing any code here

This repo enforces `AI_POLICY.md` (referenced from `CONTRIBUTING.md`). It prohibits AI-generated code, commit messages, PR descriptions, and documentation in anything **contributed upstream** to florisboard/florisboard, and forbids autonomous ("vibe coding") contributions entirely. It does not restrict private/local use (exploration, learning, a personal fork). **If any change here is destined for an upstream PR, do not author the code or the commit/PR text with AI** — flag this to the user rather than proceeding.

## Build, test, lint

```bash
./gradlew clean assembleDebug                                    # debug APK — this is exactly what CI runs
./gradlew test                                                    # all unit tests, all modules
./gradlew :app:testDebugUnitTest --tests "dev.patrickgold.florisboard.ime.window.ImeWindowControllerTest"
./gradlew :lib:kotlin:test --tests "org.florisboard.lib.kotlin.StringsTest"
./gradlew :app:lintDebug                                          # Android Lint, baseline app/lint.xml
```

- Test frameworks: JUnit5 platform + Kotest (`useJUnitPlatform()`), coverage via kotlinx-kover/JaCoCo.
- No detekt/ktlint configured — style is `.editorconfig` (`kotlin.code.style=official`) + human review only.
- CI (`.github/workflows/android.yml`) only runs `assembleDebug` — it does not gate on tests or lint.
- Requires JDK 17, Android SDK/NDK, CMake 3.22+, Clang 15+, and **Rust** (rustup + cargo on PATH) — `lib/native`'s CMake build shells out to `cargo`. Upstream officially supports Linux/WSL2 only; plain Windows is untested by them.

## Module structure (`settings.gradle.kts`)

| Module | Namespace | Purpose |
|---|---|---|
| `:app` | `dev.patrickgold.florisboard` | The IME app itself |
| `:lib:kotlin` | — (pure JVM) | Base Kotlin utils, no Android deps |
| `:lib:android` | `org.florisboard.lib.android` | Android-framework utility layer |
| `:lib:color`, `:lib:compose` | `org.florisboard.lib.*` | Compose/color utilities |
| `:lib:snygg` | `org.florisboard.lib.snygg` | FlorisBoard's own CSS-like theme stylesheet engine/DSL; JSON schema at `lib/snygg/schemas/stylesheet.schema.json` (regenerated by the `generateJsonSchema` task) |
| `:lib:native` | `org.florisboard.libnative` | The real JNI/Rust bridge: Kotlin binding + Rust crate + CMake, built into `libfl_native.so` |
| `:benchmark` | `dev.patrickgold.florisboard.benchmark` | Macrobenchmark module — **commented out** in `settings.gradle.kts`, not currently built |

Dependency layering: `lib:kotlin` ← `lib:android` ← `lib:color`/`lib:compose` ← `lib:snygg`; `:app` depends on all of them.

**Gotcha**: the top-level `libnative/` directory (no `lib:` prefix, contains `libnative/dummy/`) is an orphaned placeholder Rust crate, not referenced by any Gradle or CMake build. Don't confuse it with `lib/native`, which is the real native module.

## Core architecture (`:app`)

- **IME entry point**: `FlorisImeService` (`app/src/main/kotlin/dev/patrickgold/florisboard/FlorisImeService.kt`) extends a custom `LifecycleInputMethodService` (`ime/lifecycle/`) that makes the `InputMethodService` lifecycle/`SavedStateRegistry`-aware so Compose and Flow work inside it. UI is composed via `ime/window/ImeRootView.kt` + `ImeWindowController.kt`.
- **Composition root**: `FlorisApplication` (`FlorisApplication.kt`) calls `System.loadLibrary("fl_native")` and exposes all managers (`cacheManager`, `clipboardManager`, `editorInstance`, `extensionManager`, `keyboardManager`, `nlpManager`, `subtypeManager`, `themeManager`, ...) as `lazy` properties.
- **No DI framework** (no Hilt/Koin/Dagger). Dependencies are located via a manual service-locator pattern: `Context` extensions like `Context.keyboardManager()` walk the `ContextWrapper` chain up to the `FlorisApplication` singleton; managers pull their own deps the same way.
- **State**: `StateFlow`/`MutableStateFlow` + Compose `collectAsState`. **Prefs**: JetPref (proto-datastore-backed, KSP-processed schema in `app/.../app/AppPrefs.kt`). **Persistence**: Room, for clipboard history (`ime/clipboard/provider/`) and the user dictionary (`ime/dictionary/`).
- **Package layout**: `app/` = settings UI, one subpackage per screen, Compose Navigation via `Routes.kt`. `ime/` = actual keyboard logic (`keyboard/`, `clipboard/`, `dictionary/`, `editor/`, `nlp/`, `smartbar/`, `theme/`, `window/`, ...). `lib/` (app-local package, distinct from the top-level `lib:*` Gradle modules) = cache/crash-handling/extension/logging utilities.

## Extension system

Keyboard layouts, themes, and language packs are `.flex` archives manifested by an `extension.json`, parsed by `ExtensionMeta` (`app/src/main/kotlin/dev/patrickgold/florisboard/lib/ext/ExtensionMeta.kt`). Built-in extensions ship unzipped under `app/src/main/assets/ime/{keyboard,languagepack,theme}/org.florisboard.*/`. Theme stylesheets are written in the Snygg DSL (`:lib:snygg`). The in-app extension manager UI lives in `app/src/main/kotlin/dev/patrickgold/florisboard/app/ext/`.
